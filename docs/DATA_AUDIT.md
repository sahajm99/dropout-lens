## Headline findings

- 4,424 rows x 35 columns = **34 features + Target**. The brief said 36 features; this file is the 34-feature Zenodo/Kaggle release that accompanies the Data article. The UCI (id 697) release adds two columns that are **absent here**: `Previous qualification (grade)` and `Admission grade`. Anything downstream that expects them will break.
- No missing values, no duplicate rows, every column is integer-coded except the two grade columns and the three macro columns.
- Target: Graduate 2,209 (49.9%), Dropout 1,421 (32.1%), Enrolled 794 (17.9%).
- Codes are the sequential Table-1 codes of the Data article (1..18 for Application mode, 1..17 for Course, etc.), **not** the sparse UCI codes (1, 2, 5, 7, 10, 15, ...). Every hypothesised mapping in section 4 is supported by the data; none is contradicted.
- **180 rows (4.1%) have all twelve curricular-unit columns equal to zero, and every one of them is Course 2 (Animation and Multimedia Design) - 180 of that course's 215 rows.** That is a course-level record gap, not a student behaviour; year-1 performance features are unusable for Course 2 (section 5.1).
- `grade` = 0 exactly when `approved` = 0 (both semesters, no exceptions) and is >= 10 in every other row bar one (9.8). So `grade` is the mean mark of *approved* units and 0 is a placeholder, not a mark. The brief's suspected 'grade = 0 with approved > 0' case does not occur (section 5.2).
- `Curricular units ... (without evaluations)` does not mean what its name says: all 169 (1st sem) / 221 (2nd sem) students who enrolled but sat no evaluation have it set to 0, and it exceeds `enrolled` in 3 rows (section 5.3). Do not derive anything from it. The 'enrolled > 0 and evaluations = 0' pattern itself is a perfect semester-1 dropout marker (169 of 169 are Dropout).
- Checks that came back clean: no approved > enrolled, no approved > evaluations, no credited > enrolled, no grade outside 0-20, no age outside 17-70. Other oddities: `Application order` has one row each at 0 and 9; the three macro columns are a 10-level intake-year key (section 5).

### 5.2 Grade versus approved: grade = 0 with approved > 0 does not occur

- grade = 0 & approved > 0: **0 rows (1st sem), 0 rows (2nd sem)**. The case the brief asked about is absent.
- grade > 0 & approved = 0: **0 / 0 rows**. So `grade = 0` <=> `approved = 0` holds exactly in both semesters: 718 and 870 rows respectively (of which 180 are the Course 2 rows; the rest enrolled and passed nothing - Target of the non-Course-2 zero-approved rows: Dropout 493, Enrolled 43, Graduate 2 in semester 1).
- Minimum grade among rows with approved > 0: 9.8 (1st sem) and 10.0 (2nd sem). Only **1 / 0 rows** have a grade strictly between 0 and 10; a student who sat exams and failed everything always shows grade 0, never a failing mean.
  - The single sub-10 row (0-based index 3250): 1st sem enrolled 7, evaluations 9, approved 1, grade 9.8; Target Dropout, age 36, mode 4. One approved unit at 9.8 looks like a rounded pass (9.8 -> 10) rather than a data error.
- Conclusion: `grade` is the **mean mark of approved units**, and 0 is a placeholder for 'nothing approved'. It therefore carries no information beyond `approved > 0` at the zero boundary and is only meaningful conditional on approved > 0. Treat 0 as missing (or add a `has_grade` flag); never feed it to a model as a mark of zero.

### 5.5 Application order

- Distribution: {0: 1, 1: 3026, 2: 547, 3: 309, 4: 249, 5: 154, 6: 137, 9: 1}. One row at 0 and one at 9, nothing at 7 or 8. Under the documented 0..9 scheme both are legal, but the mass at 1..6 says the working scale is 1 = first choice to 6 = sixth choice; the 0 and 9 rows look like keying errors or a different intake system. Two rows - harmless, but do not treat 0 as 'better than 1'.

### 5.7 Outcome versus performance

- Passed every unit in both semesters: 1280 rows - Target: Dropout 66, Enrolled 63, Graduate 1151. 66 of these (5.2%) still dropped out - dropout is not purely academic (fees, debt and age carry it; see section 4.5).
- Passed nothing in either semester while enrolled in both: 496 rows - Target: Dropout 469, Enrolled 27, Graduate 0. 0 labelled Graduate, which is reassuring.
- Tuition fees not up to date: 528 rows, of which 29 graduated and 457 dropped out. The flag is recorded at a point in time close to the outcome; it is arguably a leak of the outcome rather than a predictor available at enrolment.

### 5.8 Leakage and interpretation cautions

- The curricular-unit columns describe the end of year 1; `Target` is measured at the end of the normal programme length. Any model using them predicts from year-1 performance, not from enrolment-time information. For an at-enrolment model use only the demographic, admission and macro columns.
- `Tuition fees up to date` and `Debtor` are administrative states that typically flip when a student stops attending; treat as near-outcome.
- The macro triple identifies the intake year and will absorb cohort effects. `Enrolled` share varies from 12.7% to 20.9% across the ten cohorts; the file carries no year column, so which cohorts are the recent (censored) ones cannot be confirmed here.
- Course 2 has no curricular record (section 5.1): a model that uses both `Course` and the curricular columns will encode that gap as a Course-2 effect.
